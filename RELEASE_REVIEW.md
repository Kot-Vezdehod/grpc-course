# Финальное ревью grpc-course v0.1.0

Дата: 2026-11-12. Основание: предыдущие аудиты и фактический код проекта.

**Исходники подготовлены к первому коммиту: известных секретов среди 94
кандидатов не обнаружено; build, vet и доступные unit-тесты проходят.
Публикация старого локального `order-service` блокируется: в нём подтверждены
учётные данные. Полный запуск MVP и smoke test не подтверждены из-за запрета
локальных сокетов и недоступного Docker daemon.** Значения секретов не приводятся.

## Безопасность и Git

- `git ls-files --cached --others --exclude-standard` даёт 94 кандидата первого
  коммита. Индекс пуст, коммитов нет. В доступной локальной истории, refs,
  reflog и объектах Git ранее ничего не найдено; история не переписывалась.
- Выполнено повторное сканирование кандидатов на приватные ключи, URL с
  учётными данными, присваивания паролей/токенов, литералы WithPassword,
  provider-токены, JWT и Authorization. Проверено отсутствие трёх известных
  локальных PostgreSQL-паролей и фрагментов локальных приватных ключей.
  **Совпадений нет.** Среди кандидатов нет бинарников, архивов и `.env` с секретами.
- `.gitignore` и `.dockerignore` проверены и дополнены: локальные сертификаты
  `.crt/.cer/.der`, CSR/serial-файлы, `.pgpass` и `.pg_service.conf` исключены.
  Каталог `certs/`, приватные ключи, `.env`, IDE, runtime-данные, сборочные
  артефакты и `LOCAL_DATABASES.md` остаются исключёнными.
- Проверена доступность для первого коммита protobuf `proto/`, generated Go
  `gen/`, миграций `migrations/`, мониторинга `monitoring/` и OpenAPI `api/`.
- Во всём рабочем дереве найден один бинарный артефакт: старый `order-service`.
  Он содержит известный локальный пароль и PostgreSQL URL с учётными данными.
  Git его игнорирует, Docker build context исключает. **Не включать в release
  assets или архив рабочего дерева. Публикация этого артефакта заблокирована.**
  Файл не удалён и не заменён; это требует отдельного согласования.
- Четыре приложения отдельно собраны во временный каталог вне репозитория.
  В свежих бинарниках не обнаружены известные локальные пароли, URL с
  учётными данными или материал локальных приватных ключей.
- Локальные `certs/ca.key`, `certs/order-client.key`, `certs/payment-server.key`
  и памятка `LOCAL_DATABASES.md` по-прежнему содержат чувствительные данные,
  но исключены из публикации. Не изменялись и не ротировались. При известной
  внешней передаче этих значений ротация обязательна до релиза.

Это проверка по шаблонам и известным значениям, а не гарантия отсутствия
произвольных/обфусцированных секретов. Gitleaks/TruffleHog не установлены.
Удалённые репозитории, другие клоны и резервные копии не проверялись.
`.gitignore` не защищает от принудительного добавления и не управляет файлами,
вручную прикладываемыми к GitHub Release.

## Документация

README теперь содержит описание и стек, обзор четырёх приложений, требования,
сборку, обязательные DSN, PostgreSQL-роли и миграции, создание собственных
локальных mTLS-сертификатов, команды запуска четырёх приложений, REST-примеры,
пошаговый ручной smoke test, ссылку на OpenAPI, Prometheus/Grafana, тесты и
ограничения MVP. Команды сертификатов останавливаются при существующем `certs/`
и не заменяют локальные ключи. Примеры БД не содержат паролей.

Создан `docs/architecture.md`: границы сервисов, фактические слои кода,
HTTP/gRPC-путь запроса, PostgreSQL-транзакции, алгоритм резервирования,
идемпотентность и ограничения распределённых операций. Добавлены Mermaid-схемы
компонентов и создания заказа. mTLS показан только на Order → Payment.

Grafana описана как отдельно настраиваемый потребитель Prometheus; provisioning
и дашбордов нет. Dockerfile и Inventory kind-манифесты существуют, но полный
Docker/Kubernetes-запуск не заявляется. Docker Compose отсутствует.

Bash-блоки README проверены через `bash -n`; локальные Markdown-ссылки проверены.
Рецепт mTLS выполнен в отдельном `/tmp`-каталоге: проверены назначения
серверного/клиентского сертификата, имя localhost и отказ повторного запуска
при существующем `certs/`. Сертификаты рабочего проекта не затрагивались.
Mermaid-диаграммы сверены с кодом; графический рендерер в этой проверке не применялся.

## Финальные проверки

| Проверка | Результат |
| --- | --- |
| `GOCACHE=/tmp/grpc-course-go-cache go build ./...` | PASS |
| `GOCACHE=/tmp/grpc-course-go-cache go vet ./...` | PASS |
| Отдельная сборка Order, Inventory, Payment, API Gateway | PASS, бинарники вне репозитория |
| `go test -count=1` для всех пакетов, кроме E2E и двух PostgreSQL integration packages | PASS; пакеты без тестов отмечаются Go отдельно |
| E2E без явного включения | SKIP; не считается подтверждением сценария |
| Docker daemon | `docker info` → permission denied для `unix:///var/run/docker.sock` |
| Полный `go test -count=1 ./...` на текущем этапе | Не запускался после недоступности Docker; предыдущий полный прогон завершился с ошибками двух Testcontainers-пакетов по той же причине |
| Полный запуск приложений и smoke test | Не подтверждены: локальные TCP-сокеты запрещены, тестовые DSN не заданы |

Unit-прогон исключает только `e2e`, `internal/order/adapters/postgres`,
`internal/inventory/adapters/postgres`. Все остальные пакеты проверены, включая
Gateway, ранее исправленные тесты конструкторов и обязательной конфигурации.
Новых тестов на этом этапе не добавлено. Go: `go1.27.3-X:nodwarf5 linux/amd64`;
`go.mod` требует Go 1.27.1. Зависимости не менялись.

Проверка запуска каждого свежего бинарника выполнена без доступа к пользовательским
базам и без изменения данных:

- Order, Inventory, Payment без соответствующего DSN завершаются с кодом 1
  и ожидаемой ошибкой `<ИМЯ_ПЕРЕМЕННОЙ> is required`.
- С синтаксически корректным DSN без пароля на тестовый локальный порт они
  проходят проверку конфигурации и доходят до Ping, который блокируется
  ограничениями сокетов. Это не успешное подключение к PostgreSQL.
- Gateway доходит до открытия HTTP-порта и завершается из-за запрета сокетов.
- Подключения к локальным PostgreSQL/gRPC/HTTP-портам также недоступны из среды.
  Docker socket не обходился; права, группы, сервисы и кластеры не менялись.

Без подтверждённой изолированной инфраструктуры smoke test не выполнялся.
В README приведены уникальные тестовые ID и ожидаемый ход: товар stock=10,
заказ с quantity=2, stock=8, точный повтор заказа → 409 и stock по-прежнему 8.
Эти значения здесь являются ожиданиями по коду, а не результатом выполненного
smoke test. Проверка не создавала/удаляла записи в пользовательских БД.

## Изменённые файлы текущего этапа

1. `.gitignore` — дополнительные исключения локальных сертификатов и PostgreSQL-конфигурации.
2. `.dockerignore` — соответствующие исключения build context.
3. `README.md` — полная инструкция MVP и ограничения.
4. `docs/architecture.md` — новый документ с двумя Mermaid-диаграммами.
5. `RELEASE_REVIEW.md` — этот итоговый отчёт.

Результаты предыдущего этапа сохранены: обязательные DSN без fallback,
очищенные E2E/Kubernetes-примеры, исправленные конструкторы unit-тестов,
генерируемые Testcontainers-пароли. Текущий этап не изменяет Go-код,
protobuf-контракты, архитектуру, миграции, мониторинг и пользовательские данные.
Это проверяется сравнением SHA-256 до/после.

## Оставшиеся проблемы и действия до публикации

| Приоритет | Проблема / действие |
| --- | --- |
| High — BLOCKER для артефакта | Старый `order-service` содержит учётные данные. Не публиковать и не включать в архив рабочего дерева. Удаление/замена или иное устранение согласовывается отдельно; свежие проверенные бинарники собраны вне дерева. |
| High — условно | При прежней внешней передаче ключей/паролей требуется ручная ротация CA/сертификатов и паролей. Сам факт внешней утечки не установлен. |
| Medium | Повторить полный `go test -count=1 ./...` с доступным Docker и образами Testcontainers. |
| Medium | На отдельной инфраструктуре выполнить запуск с собственными DSN/сертификатами, ручной smoke test и, при необходимости, явный E2E. |
| Medium — известные ограничения MVP | Нет общей транзакции и компенсации; повтор Order не восстанавливает незавершённую оплату; GET товара возвращает неверный product_name. Ограничения явно описаны; бизнес-логика по заданию не менялась. |
| Low | Проверить Docker-сборку, если контейнеры будут частью релиза; Kubernetes/Compose не заявлять как готовое окружение. |
| Low | Выбрать лицензию, если предполагается разрешить использование третьими лицами; файл лицензии отсутствует. |

Перед первым коммитом подготовить индекс вручную, сверить список с ожидаемыми
исходниками и повторить сканирование именно индекса. Release assets проверять
отдельно. Не добавлять принудительно локальные ключи, сертификаты, памятки,
старые бинарники и runtime-данные. Для исходников предпочтителен архив
проверенных файлов Git, а не всего рабочего каталога.

Коммиты, push, теги, создание публичного репозитория, удаление пользовательских
данных, ротация секретов и переписывание истории не выполнялись. Работа
остановлена для ревью: кандидаты первого коммита проверены, полная работоспособность
MVP в доступном окружении не подтверждена.
